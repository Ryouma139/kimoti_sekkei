### 0.2 画面ごとの変更内容

**① 管理画面のトークン（#1）**
- オフ（タブを閉じるまで）で設定したトークンは、ホームなど**管理画面の外のページを開いた時点で消えます**。管理画面の中（トップ ⇔ 各フォーム ⇔ 一覧）を行き来する間は残ります。
- 「このブラウザに保存する」オンのトークンは残します。
- ブラウザの「戻る」で管理画面に戻った場合も、`pageshow` で表示を今の状態（未設定など）に合わせ直します。

**② 保存記事一覧（#2・#3）**
- 管理画面の上部の切り替えメニュー（`AdminNav`）：**記事を書く／保存記事一覧／カテゴリ**。
- 各行：タイトル・種類・下書きの印・日付・ファイルのパス・リンク（下の表）。

| リンク | 表示する条件 | 動き |
|---|---|---|
| サイトで見る | 公開中の記事 | サイトの記事ページへ |
| 管理画面で修正 | **トークン設定時** | その種類のフォームを修正モードで開く（④） |
| GitHubで編集 | **トークン設定時** | GitHub の編集画面を新しいタブで |

- トークン未設定なら「『記事を書く』で設定してください」と案内。表示を隠すだけで、実際に編集できるかは GitHub の権限で決まります。

**③ 修正モード（#4・#5）**
- 一覧の「管理画面で修正」→ `/admin/learn/?edit=src/content/learn/2026-10-04_iam-policy.md` のように開く。
- GitHub から今のファイルを読み、front matter（`yaml` パッケージ）と本文をフォームへ。上に「修正中：<ファイル>」、ボタンは「修正を保存」。
- **日付・スラッグは変更不可**（ファイル名＝URL に使うため）。**保存先は読み込んだファイルに固定**なので、ファイル名は変わりません。
- `created` は元の値を残す。feel の1日1件・スラッグ形式のチェックは修正時は省略。
- 読み込んだあとに GitHub 側で変わっていたら保存しない（sha を比較）。
- 新規作成で、確認のあと保存までの間に同じファイルが作られた場合（GitHub が 422 を返す）も「同じファイル名の記事がすでにあります」と表示。

**④ ホームのポップアップ（#6）**
- 「本日の気持ちが入力されていません。」＋「書く」（`/admin/feel/` へ）／「あとで」（その日はタブを閉じるまで出さない）。
- 最初は管理画面に出していたが、**ホームで全員に出す**形に変更（管理画面からは削除）。
- 判断：開いた時点のブラウザの日付（日本時間）→ ビルド時点の一覧（下書き含む）→ なければ GitHub に `src/content/feel/<今日>.md` があるか確認。**保存トークンが無効でも、トークンなしで確認し直す**。確認できない（通信エラー等）ときは出さない。
- 手元で今日の日記を消しても、**GitHub に残っていれば出ません**（GitHub も見るため）。

**⑤ デザインが外れる問題（#7）**

| | 内容 |
|---|---|
| 症状 | 公開サイトで、時間がたつと白い背景にリンクと巨大な黒丸（顔アイコンの目）だけになる |

## 1. 全体の仕組み

```
記事（Markdown）── src/content/feel・tech・learn
カテゴリ（JSON）── src/data/categories.json
   │  手元で書いて push ／ 管理画面で保存（GitHub に直接コミット）
   ▼
GitHub（main ブランチ）
   │  push・毎日 0:00（日本時間）・手動 で GitHub Actions が動く
   ▼
ビルド（astro check && astro build）
   │  記事を全部読み、集計（カレンダー・学習時間・連続日数など）して HTML を作る
   ▼
GitHub Pages で公開（静的サイト）
```

- **DB は使いません。** 記事はリポジトリ内の Markdown が正です。必要性（書くのは1人・全員に同じページ）、運用（無料・保守ほぼ不要）、安全（公開は HTML だけ）、履歴（Git の差分で残る）の理由から。
- 集計はすべて**ビルド時**。「今日」は**ビルドした日（日本時間）**なので、毎日 0:00 に自動でビルドし直しています。
- ただし**ホームのポップアップ**と**管理画面**は、ブラウザ側で GitHub の最新の状態も確認します。

## 3. 記事データの仕様

### 3.1 項目（`src/content.config.ts`）

**共通**

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | ○ | タイトル |
| `date` | ○ | 日付（`2026-10-04`）。カレンダー・並び順の基準 |
| `created` | | 書いた日時（`"2026-10-04T21:30:15+09:00"`）。管理画面で保存すると自動で入る。同じ日付の並び順に使う |
| `tags` | | タグの配列。省略時 `[]` |
| `draft` | | `true` で**サイトのどこにも出ない**（下書き）。省略時 `false` |

- **きもち日記（feel）**：`mood`（必須：`great` / `happy` / `calm` / `meh` / `down`）、`weather`（任意）
- **まなびログ（learn）**：`minutes`（必須：1以上の整数・分）、`category`（必須：`src/data/categories.json` のどれか）、`project`（任意：テックノートの id）、`source`（任意：URL）
- **テックノート（tech）**：`type`（必須：`project` / `note`）、`updated`（任意）、`summary`（任意）。`project` のときだけ：`icon`（3文字まで）、`status`（`plan` / `run` / `done`）、`progress`（0〜100）、`stack`（配列）、`repo`（URL）

項目の決まりに合わない記事（例：`categories.json` にないカテゴリ）があると**ビルドが失敗し、公開されません**。

### 3.2 ファイル名・id（スラッグ）

ファイル名（拡張子なし）が記事の id になり、URL に使われます（英字は小文字になる）。

| 種類 | 管理画面で作るファイル名 | URL |
|---|---|---|
| feel | `2026-10-04.md`（**1日1件**） | `/feel/2026-10-04/` |
| learn | `2026-10-04_iam-policy.md`（日付_スラッグ） | `/learn/#2026-10-04_iam-policy` |
| tech | `2026-10-04_my-app.md`（作成日_スラッグ） | `/tech/2026-10-04_my-app/` |

- スラッグはタイトルとは別に入力。**英小文字・数字・ハイフン**だけ。
- タイトルは重複してもよい。**日付＋スラッグ（＝ファイル名）が同じ**ときだけ新規保存を止める。
- ファイル名を変えると URL が変わる（テックノートは、まなびログの `project:` も直す必要あり）。

### 3.3 下書き（`draft: true`）

- 記事の読み込みは `getFeel` / `getTech` / `getLearn` を通り、下書きを除く。一覧・詳細（ページを作らない）・統計・カレンダー・タグ・ポップアップ以外の集計に出ない。
- 管理画面の**保存記事一覧**（`getAllForAdmin`）にだけ出る。
- リポジトリは公開なので、GitHub 上では誰でも読める。
- 公開するには、**保存記事一覧の「管理画面で修正」で下書きを外す**か、GitHub・エディタで直す。

### 3.4 並び順（`byDateDesc`）

1. `date` が新しい順 → 2. 同じ日付なら `created` が新しい順 → 3. `created` なしはその日の中でいちばん古い扱い → 4. それ同士はファイル名の順

## 5. 管理画面

ブラウザのフォームで書き、**GitHub のリポジトリに直接コミット**します。保存後、自動デプロイで公開されます。

### 5.1 画面

| URL | 内容 |
|---|---|
| `/admin/` | **記事を書く**。3種類の入口カード（記事数・最新の日付）と GitHub トークンの設定 |
| `/admin/feel/`・`/learn/`・`/tech/` | 各記事のフォーム（新規／`?edit=` で修正） |
| `/admin/posts/` | **保存記事一覧**（V2） |
| `/admin/categories/` | **カテゴリ**（V2） |

- 上部の切り替えメニュー：**記事を書く／保存記事一覧／カテゴリ**。フォームでは「記事を書く」が選択中。
- サイドバーには出さない。`noindex`。
- 記事フォーム・カテゴリでは、トークン未設定なら「保存できません」の警告。

### 5.2 フォームの項目

| 項目 | feel | learn | tech |
|---|---|---|---|
| タイトル | ○ | ○ | ○ |
| 日付 | ○（今日） | ○（今日） | 作成日○（今日）・更新日 |
| スラッグ | — | ○ | ○ |
| その他 | 気分（顔アイコン・初期値おだやか）、天気 | 時間（分・初期値30）、カテゴリ、関連プロジェクト、参考URL | 種類、概要。プロジェクトのとき：アイコン文字・状態・進捗・技術スタック・リポジトリURL |
| タグ／下書き／本文 | ○ | ○ | ○（本文の初期値「## 背景／## 決定／## 理由」） |

- 選択肢は `moods.ts`・`categories.json`・テックノートのプロジェクト（ビルド時点）から。
- 下に「保存先：<ファイル名>」と「保存される内容を見る」。

### 5.3 新しく保存する流れ

```
「保存して公開」→ preventDefault() → トークン確認 → 入力チェック
→ GitHub に同じファイルがあるか（あれば止める）→ 作成してコミット
→ 「保存しました」＋「コミットを見る」、フォームを空に → 1〜2分後に公開
```

| 入力チェック | 内容 |
|---|---|
| 共通 | タイトル・日付・本文が空でない |
| feel | その日のきもち日記がないか（1日1件） |
| learn | スラッグの形式、時間が1以上の整数、参考URL |
| tech | スラッグの形式、更新日 ≧ 作成日、（プロジェクト）アイコン3文字まで・進捗0〜100・リポジトリURL |
| 全種類 | 同じファイル名がある（同時保存の 422 も含む）→「同じファイル名の記事がすでにあります」 |

| エラー | メッセージ |
|---|---|
| トークン未設定 | GitHub トークンが設定されていません… |
| トークン不正・期限切れ（401） | トークンが正しくないか、期限切れです… |
| 書き込み権限なし（401/403） | 書き込む権限がありません… |
| 通信できない | 通信に失敗しました… |

### 5.4 保存記事一覧 `/admin/posts/`

0.2 ② のとおり。並びは 3.4 と同じ。**一覧はビルド時点のもの**（保存直後の記事はデプロイ後に載る）。閲覧にトークンは不要。

### 5.5 修正（`?edit=`）

0.2 ③ のとおり。**注意**：front matter はフォームの項目だけで作り直すので、手で書いたコメントやフォームにない項目は消えます。

### 5.6 カテゴリ `/admin/categories/`

`src/data/categories.json`（`[{ "name": "AWS", "color": "#F59E0B" }, …]`）を編集する画面です。

```
「保存して公開」
 ① トークン確認 ② GitHub の最新を読み込めているか（読めない理由を表示）
 ③ 新しい一覧を作る（色の変更＋追加）
 ④ チェック：変更なし／同じ名前（大文字小文字区別なし）／20文字超
 ⑤ 読み込んだあとに GitHub 側で変わっていないか（sha）
 ⑥ categories.json をコミット（例「カテゴリ: 「Docker」を追加・色を変更（TypeScript）」）
 ⑦ 数分後に、サイトの色・まなびログのフォームの選択肢に反映
```

- 各カテゴリに記事数（下書き含む・ビルド時点）を表示。
- **名前の変更・削除はできない**（記事の `category` と合わなくなるとビルドが失敗するため）。
- `categories.json` が GitHub にまだないと「まだ GitHub にありません。commit・push してから使ってください」。

### 5.7 できないこと・注意

- **記事の削除と、ファイル名（日付・スラッグ）の変更**はできない（GitHub かエディタで）。
- 保存先は**いつも GitHub**。`npm run dev` の管理画面で保存しても手元には入らない → `git pull`。

## 6. GitHub トークン

| 項目 | 内容 |
|---|---|
| トークンとは | パスワードの代わりの「合い鍵」（`github_pat_...`）。作るときに決めた範囲だけ使え、期限を付けられ、漏れても消せば終わり |
| 作り方 | Settings → Developer settings → Fine-grained tokens → 対象は **kimoti_sekkei だけ**、権限は **Contents: Read and write** だけ、期限付き。表示は一度だけ |
| 設定 | 「記事を書く」のトークン欄に貼って「設定する」 |
| 保存（オン） | localStorage。ブラウザを閉じても残る |
| 保存（オフ） | sessionStorage。**管理画面にいる間だけ**（外のページを開く・タブを閉じると消える） |
| 範囲 | ブラウザ・端末ごと。公開サイトと localhost も別 |
| 他の人 | 投稿できない（書き込み権限があるのは Ryouma139 だけ）。例外：端末を使われる・漏れる・共同編集者を追加 |
| 忘れた・期限切れ | 見直せないので作り直す（Regenerate または新規作成＋古いものを Delete） |
| push の認証（参考） | `.github/workflows/` を変えて push するには GitHub CLI に `workflow` の許可が必要（`gh auth refresh -h github.com -s workflow` → `gh auth setup-git`） |

## 7. 公開（GitHub Pages）

| 設定 | 内容 |
|---|---|
| `astro.config.mjs` | `site: 'https://ryouma139.github.io'`、`base: '/kimoti_sekkei'`、`build.inlineStylesheets: 'always'`、JS のファイル名固定（`stable-client-file-names`） |
| Settings → Pages → Source | GitHub Actions |
| `deploy.yml` | `main` への push・毎日 0:00（`cron: '0 15 * * *'`）・手動 |

- ページ内のリンクは必ず `url()` を通す。手元も `http://localhost:4321/kimoti_sekkei/` で開く。
- デプロイ直後の10分ほどは「古い HTML ＋ 新しい JS」になりうる（崩れはしない。動きが変なら再読み込み）。

## 8. よくある質問

| 質問 | 答え |
|---|---|
| 管理画面で保存したのに手元に出ない | 保存先は GitHub。`git pull` |
| 公開サイトに出ない | 1〜2分待つ。Actions の失敗・`draft: true` を確認 |
| 公開サイトのデザインが外れた | V2 の修正（#7）以降は起きない。それ以前のページは Ctrl+F5 |
| ポップアップが出ない | 今日の日記が GitHub にある／「あとで」を押した（タブを閉じるまで出ない）／古い HTML（Ctrl+F5） |
| 記事のファイル名を変えずに直したい | 保存記事一覧の「管理画面で修正」（日付・スラッグは固定） |
| 同じタイトル・スラッグだと？ | タイトルは重複可。日付＋スラッグが同じだと新規保存できない |
| カテゴリを増やしたい | 管理画面の「カテゴリ」。名前の変更・削除は GitHub かエディタで（記事側も直す） |
| 年が変わったらコードの追加は？ | 不要（カレンダーの年は自動） |
| トークンを毎回入れる？ | 「このブラウザに保存する」オンなら不要 |
